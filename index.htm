Страница 2

Вступление

Объекты интереса ранга «Alpha» — .exe-inject и DoomsDay.

Помимо этого, информация, которая даётся на этом ранге, позволяет расширить или оптимизировать возможности проверяющего в ходе проверки «Beta» путём дополнительных или альтернативных методов.

Три программы, которые добавляются и используются в зависимости от выбора на данном ранге – это ExecutedProgramsList, WinPrefetchView и SystemInformer.

На своё усмотрение и в зависимости от своих умений проверяющий может воспользоваться одной из вышеперечисленных программ в дополнение к программам ранга Beta. Наиболее предпочтительным вариантом (и рекомендуется пользоваться именно этой программой) является проверка с помощью SystemInformer. Благодаря ней можно проверить и на использование .exe-inject, и .dll-inject, и предположить использование хитбоксов в игре. Менее предпочтительная – ExecutedProgramsList.

Также допустимо (и рекомендуется) использовать сканер Ocean для скорой поверхностной проверки ПК игрока и получения дополнительной информации. В некотором смысле Ocean заменяет JournalTrace и EPL/WPV/SI (даёт ту информацию, которую выводит и сканер). Руководство по использованию этой программы вынесено в отдельный документ (см. закреплённое сообщение беседы ранга Alpha).

Страница 3

Регламент проверки

  • На ранге «Alpha» добавляются программы: ExecutedProgramsList, WinPrefetchView, SystemInformer, Ocean. Использование прочих новых программ запрещено (кроме тех, что даны в Beta).
  • Регламент проверки игрока по рангу «Alpha»:
    • Если у сотрудника должность «Модератор»: на игрока должны быть репорты, в частности, в день проведения проверки, либо игрока уже проверяли по Beta.
    • Если у сотрудника должность «Первый Модератор» или выше, то проверка по данному рангу для него обязательна в любом случае. Он вправе выбрать одну из 3 программ (EPL, WPV или SI), которую будет использовать в дополнение к имеющимся на ранге Beta (Everything и JournalTrace).
    • *При этом, если игрока проверял либо сотрудник ранга Alpha+, либо ранга Method, вызывать такого игрока нет смысла за исключением, если с момента проверки прошло не менее недели.
  • Требовать AnyDesk можно в трёх случаях: 1) когда этого требует руководство; 2) когда обнаружен лоадер/папки .exe inject’а, .exe-launcher’а, DoomsDay; на ПК есть хитбоксы или гост-клиенты; 3) когда обнаружено удаление .exe-файла или .jar-файла в день проверки через JournalTrace. Предварительно вы обязаны предупредить о бане за отказ от использования AnyDesk. Если игрок всё равно отказался – баним на 14 дней (если требуем из-за наличия чита или удаления, то эту причину и оглашаем).
  • Внимательно следите за тем, чтобы человек не записывал вашу проверку (OBS, NVIDIA, Bandicam…). Обнаружить это можно просто глазами, через Диспетчер задач / SystemInformer или Alt+Z (NVIDIA).
Страница 4

JournalTrace. Проверка очистки Cortex’а

Перед тем, как перейти к новым программам, необходимо разобрать метод, позволяющий доказать использование Cortex’а через JournalTrace ввиду автоудаления .pf-файла.

При инжекте/использовании cleaner’а иногда Cortex удаляет за собой .pf-файл с названием лоадера чита (например, SAFARI.EXE.PF). Это возможно обнаружить через программу JournalTrace.

Для этого необходимо воспользоваться Directory Tree, перейдя по пути C:\Windows\Prefetch. Сортируем по дате. Необходимо найти «File delete» напротив .pf-файла. Также можно воспользоваться Data Grid, введя туда .pf и отсортировав по дате.

Страница 5–7

ExecutedProgramsList

Программа позволяет проверить запускавшиеся ранее .exe-файлы, включая .exe-inject.

Вариант 1. Сортировка по «Last Executed On»

Проверка запускавшихся .exe файлов до времени проверки (за день). Например, проверка началась 26.09.24 13:30, проверяем те .exe-файлы, которые запускались 26 сентября до 13:30. В первую очередь обращаем внимание на файлы с пустыми «File Description», «Product Name», «File Versions» и/или «Company Name». Далее, если подозрительный файл обнаружен, ПКМ → «Open folder in Explorer» или Ctrl+O.

Вариант 2. Двойная сортировка

Сначала по «Last Executed On», затем по «Product Name» или «Company Name». Создаётся двойная сортировка – по времени последнего запуска и по отсутствию информации о программе. Если не сработало – сортируем по Product/Company name и используем Ctrl+F с сегодняшней датой.

Вариант 3. Сортировка по размеру (File size)

От большего к меньшему. Подходит для поиска Cortex’а. *Cortex подчищает за собой .pf-файл, поэтому если повезёт, данный чит-клиент окажется здесь благодаря записям в реестре.

Страница 8–9

WinPrefetchView

Программа для детального анализа папки Prefetch. В отличие от папки позволяет проверять несколько дат запуска, отображаются иконки, путь до файла, а также с чем взаимодействовали процессы. Для работы нужно сортировать по Last Runtime.

При запуске .exe-inject часто используются два процесса – conhost (командная строка) и consent (права администратора). Если нажать на любой из этих процессов и проверить данные в панели снизу, можно обнаружить упоминание .exe-inject (пользуемся Everything для проверки файлов).

cmd.exe – через этот процесс возможно обнаружить использование .bat-файла (очистка информации или аккуратный запуск чита). При обнаружении используем Everything и открываем .bat через Блокнот. DoomsDay использует Java, отображается во взаимодействии с процессом java.exe/javaw.exe.

Страница 10

Расширенные возможности WinPrefetchView

  • Options > «Hide Programs Under Windows Folder» – скрывает .exe-файлы из папки Windows, сокращает список.
  • Столбец «missed processes» – позволяет определить, удалён ли .exe-файл. Сортировку по нему проводить после сортировки по «Last Run Time».
Страница 11

Общая теория вписанных функций

Вписанная функция – чит-функция, оформленная в существующих классах (.class) какой-либо модификации. Пример – Hitboxes in Neat (21,8 кб). Обнаружить подобное чит-по возможно лишь посредством SystemInformer (для Forge) или Luyten. В Alpha рассматривается только способ нахождения через SystemInformer.

Для поиска hitboxes как вписанной функции используются KeyInputEvent (регистрирует использование клавиш для активации) и RenderPlayerEvent (выполняет механизм чит-функции).

Страница 12–13

SystemInformer — метод ASM

Для поиска хитбоксов через SystemInformer используется метод ASM (актуален только для Forge). Применяется при наличии самописных модификаций в папке mods. ASM также является альтернативой JournalTrace ~ mods.

При работе с методом ASM процесс javaw.exe требует особой расстановки галочек и цифры 20, чтобы ПК у игрока не завис. Правильно профильтровав, увидим список всех запущенных Event’ов для Forge, вместе с ними – список работающих модификаций. Помимо поиска хитбоксов можно обнаружить и перемещённые запрещённые моды.

Обратите внимание! Виден путь до интересующего нас .class (например, vazkii > neat > ToggleKeybind или HealthBarRenderer).
Страница 14–15

Проверка на .dll-inject

Dll-inject ищется через процесс javaw.exe в SystemInformer. Инструкция:

  1. Нажать ЛКМ по javaw.exe (выбрав тот, что потребляет больше памяти) 2 раза → раздел Modules.
  2. Отсортировать по Description (следует и LoadTime). В начале списка должны быть .dll без описания.
  3. ПКМ по колонке Name → choose the columns → перекинуть Load time, TimeLine и File Name.
  4. Обращаем внимание на подозрительный File name (путь), Load Time, Timeline. ПКМ → Open file location. Сверяемся с таблицей.

Unloaded modules: ПКМ по javaw.exe → Miscellaneous → Unloaded Modules. Проверяем подозрительные файлы, затем Everything и сверка по таблице.

Страница 16–19

Проверка процессов/служб через SystemInformer

Основная суть работы с SystemInformer – проверка памяти процессов для поиска упоминаний .exe inject и DoomsDay. Перед работой: открыть программу с правами Администратора, активировать галочку «Enable kernel-mode driver» (Options).

explorer.exe – отвечает за запущенные приложения в течение сеанса. Два фильтра (Regex case insensitive): ^file:///.+.exe (можно заменить на .zip, .rar, .jar, .bat) и ms-shellactivity (нивелирует обход с запуском .exe из архива).

power / dcomlaunch – позволяют обнаружить использование DoomsDay. Фильтр: -jar или .jar.

Страница 20–21

Возможные обходы проверки

Исключения в Everything: Проверить «Сервис» → «Настройки» → «Исключения». Убедиться, что нет галочек на «Исключать скрытые файлы и папки» и «Исключать системные файлы и папки», удалить директории из списка исключений.

Неработоспособность JournalTrace: Альтернатива – Process Hacker / SystemInformer ~ Handles (javaw.exe). Метод позволяет выяснить, какие моды использовались (если переносились – их новое название, удалялись – можно определить). Сортировка – Type (File). Handles показывает перенесённые и удалённые моды ($Deleted или $Recycle.Bin).

Внешний носитель: Игрок мог использовать чит-клиент на USB-флешке. System Informer – Options – Disk Devices – ПКМ по Вн. нос. – Properties – Сведения – Дата последнего удаления. Метод особенно полезен, когда отображается два отключённых внешних устройства.
